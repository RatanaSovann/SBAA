You control what it is allowed to choose from

Those placement types are an editable list, not something baked into the code. Each entry is a name plus a description, and the description is sent to the model word for word — it is what tells the model what counts and, just as importantly, what to rule out. Adding an entry here is how you point it at something new.

This matters more than it looks, because a missing type does not come back blank. The model is asked to pick the best match from the list, so a placement with no bucket comes back confidently labelled as the nearest one instead — a Hisense backdrop wall in the VAR room was called an LED Board until Wall existed as an option. For motorsport, this is where sidepod, rear wing, halo, driver suit and pit wall would be added before the first event.

The outputWhat gets handed over

The analyst picks up to two examples per placement, drags a box around the branding, and approves. Export produces one Excel workbook, one sheet per brand, one row per approved example — asset, frame number, timestamp, and the image with the box burned in.

HonestyWhat this prototype can't do

  1. It gets things wrong, confidently. In this same run the trophy in a Louis Vuitton presentation trunk was classified as an Adidas Trophy placement. There is no Adidas branding in that frame. The analyst review step exists precisely for this — nothing is accepted automatically — but do not read the candidate lists as findings.
  2. Reading text off signage is doing most of the work. That is ideal for static perimeter boards in even light. On a car at 200 mph — small, curved, motion-blurred, often no text at all — it is the technique that transfers worst. Motorsport would likely need a detector trained on liveries instead.
  3. Every box is drawn by hand. An open-vocabulary detector was tested and failed completely on perimeter boards and jerseys, so it was dropped. That is why box-drawing is the scaling bottleneck above.
  4. It is one app on one laptop. CPU-only, single video at a time, no queue, no users, no test suite. Fine for proving the idea; not what you would run weekly against a race calendar.
  5. A missing placement type becomes a wrong answer, not a blank. The model picks the nearest option from a fixed list, so motorsport categories (sidepod, rear wing, halo, driver suit, pit wall…) would need adding before the first real event.

NextIf this goes further

  1. Run the vision-model calls in parallel. Small change, turns hours into minutes.
  2. Move ingest and ranking off the browser session into a queue with workers; keep the app for review only.
  3. Get a GPU. The staged design came from not having one; a detector needs one.
  4. Fine-tune a detector on liveries. Highest value — it fixes recall on cars and proposes the boxes, which is the analyst-time problem.
  5. Use the contracted asset list. In motorsport you already know which brands should appear, which turns open discovery into checklist verification — a much easier question.
